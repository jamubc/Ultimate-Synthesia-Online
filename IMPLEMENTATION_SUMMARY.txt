3. RECORDING ARCHITECTURE
================================================================================

APPROACH: ScriptProcessorNode

Why ScriptProcessorNode?
  ✅ Broader browser compatibility
  ✅ Direct access to audio samples
  ✅ Real-time processing capability
  ✅ Works in Chrome, Firefox, Safari, Edge

Architecture Flow:

  Microphone
      ↓ [getUserMedia - MediaStream API]
  MediaStreamSourceNode
      ↓
  GainNode (Input Level: 0-200%)
      ↓
      ├─→ AnalyserNode (Input Metering)
      ├─→ ScriptProcessorNode (Recording)
      └─→ GainNode (Monitor Level: 0-100%)
            ↓
        Destination (Speakers)

Recording Process:
  1. Capture in 4096-sample chunks
  2. Store as Float32Array
  3. Accumulate in memory
  4. Combine into AudioBuffer on stop
  5. Save as take with metadata

Storage:
  - Mono: 1 channel
  - Sample Rate: 44.1kHz or 48kHz (native)
  - Format: 32-bit float
  - Memory: ~1.2MB per minute

4. HOW AUDIO IS CAPTURED AND STORED
================================================================================

Step 1: Microphone Permission
  navigator.mediaDevices.getUserMedia({
      audio: {
          echoCancellation: false,
          noiseSuppression: false,
          autoGainControl: false,
          latency: 0
      }
  })

Step 2: Audio Chain Setup
  audioInputSource → audioInputGain → audioInputAnalyser
                                    ↓
                              monitorGain → destination
                                    ↓
                           recordingProcessor

Step 3: Real-time Capture
  recordingProcessor.onaudioprocess = (e) => {
      const inputData = e.inputBuffer.getChannelData(0);
      const chunk = new Float32Array(inputData);
      recordedAudioChunks.push(chunk);
  };

Step 4: Buffer Assembly
  - Combine all chunks into single AudioBuffer
  - Calculate total length
  - Copy data with proper alignment
  - Store in slot's audioBuffer property

Storage Structure:
  loopSlotsData[slotId] = {
      recordingMode: 'audio',           // or 'midi'
      audioBuffer: AudioBuffer,         // current audio
      audioTakes: [{                    // all takes
          buffer: AudioBuffer,
          name: "Take 1",
          timestamp: 1699123456789
      }],
      currentTakeIndex: 0,
      isArmedForAudio: true,
      audioPlaybackSource: null
  }

6. LATENCY AND MONITORING
================================================================================

Latency Measurement:
  baseLatency = audioContext.baseLatency        // Processing latency
  outputLatency = audioContext.outputLatency    // Hardware latency
  totalLatency = (baseLatency + outputLatency) * 1000 ms

  Typical Values:
    • 10-30ms: Good (barely noticeable)
    • 30-50ms: Acceptable (slight delay)
    • >50ms: Noticeable (may need compensation)

Monitoring System:
  Direct Monitoring:
    ✅ Toggle to enable/disable
    ✅ Hear yourself while recording
    ✅ Independent volume control
    ✅ Prevents feedback when used with headphones

  Input Metering:
    ✅ Real-time visual feedback
    ✅ RMS-based level calculation
    ✅ -60dB to 0dB range
    ✅ Color-coded: Green → Yellow → Red
    ✅ Helps set optimal input levels

Latency Compensation:
  - System measures and displays latency
  - Users aware of monitoring delay
  - Can compensate by:
    • Using lower buffer sizes
    • Using ASIO/CoreAudio drivers (desktop)
    • Accepting latency for non-critical recording

7. TAKE COMPING SYSTEM
================================================================================

Multiple Takes:
  ✅ Each recording to same slot creates new take
  ✅ Previous takes preserved automatically
  ✅ Stored with metadata (name, timestamp, duration)
  ✅ Unlimited takes per slot (memory permitting)

Switching Takes:
  switchAudioTake(slotId, takeIndex)
  - Changes active take
  - Updates waveform visualization
  - Next playback uses selected take

Take Data:
  slot.audioTakes = [
      {buffer: AudioBuffer1, name: "Take 1", timestamp: ...},
      {buffer: AudioBuffer2, name: "Take 2", timestamp: ...},
      {buffer: AudioBuffer3, name: "Take 3", timestamp: ...}
  ]
  slot.currentTakeIndex = 1  // Playing Take 2

Future Enhancement - Section Merging:
  compTakes(slotId, [

      {takeIndex: 1, start: 2, end: 4},    // Use Take 2 for 2-4 seconds
      {takeIndex: 0, start: 4, end: 6}     // Use Take 1 for 4-6 seconds

12. TROUBLESHOOTING
================================================================================

Problem: "Failed to access microphone"
  → Check browser permissions
  → Ensure mic is connected
  → Use HTTPS or localhost
  → Try different browser

Problem: Input meter not moving
  → Check system mic settings
  → Increase input level slider
  → Select correct input device
  → Make sound near microphone

Problem: Feedback/echo when monitoring
  → Disable direct monitoring
  → Use headphones instead of speakers
  → Reduce monitor level

Problem: Latency too high
  → Close other applications
  → Use ASIO/CoreAudio drivers
  → Accept latency for non-realtime use

Problem: No waveform after recording
  → Check browser console (F12)
  → Verify recording completed
  → Ensure audio was captured (meter moved)
  → Try recording again
