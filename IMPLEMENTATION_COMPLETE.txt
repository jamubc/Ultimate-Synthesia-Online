========================================================================
ARCHITECTURE SUMMARY
========================================================================

1. TRANSPORT CONTROL ARCHITECTURE
   - State Machine: STOPPED | PLAYING | PAUSED | RECORDING | COUNT_IN
   - Position Tracking: transportPosition (seconds)
   - Sync: audioContext.currentTime based
   - Animation: requestAnimationFrame loop at 60fps

2. TEMPO AUTOMATION IMPLEMENTATION
   - Data: Array of {bar, bpm, curve} objects
   - Conversion: barsToSeconds() considers tempo changes
   - Visualization: Canvas-based tempo lane graph
   - Live Updates: Tempo changes apply during playback

3. TIME SIGNATURE HANDLING
   - Current: {numerator: 4, denominator: 4}
   - Changes: Array of {bar, numerator, denominator}
   - Affects: Bar duration calculations
   - Display: Shows in transport toolbar

4. MARKER/REGION SYSTEM
   - Storage: Array of {name, position, color}
   - Rendering: DOM elements on timeline
   - Interaction: Click to jump, right-click to delete
   - Colors: 7 predefined colors cycling

5. PLAYHEAD SYNCHRONIZATION APPROACH
   - Real-time: Updates via requestAnimationFrame
   - Position: transportPosition = audioContext.currentTime - transportStartTime
   - Visual: CSS left property updated each frame
   - Auto-scroll: Smart centering with margins

KNOWN LIMITATIONS

2. Maximum 960 ticks per beat (MIDI standard)

4. Marker limit: None (but DOM may slow with 1000s)
5. No MIDI timecode sync (future feature)
